# 신민근 포트폴리오

정적 웹사이트입니다. 빌드 도구나 설치 과정이 없고, `index.html`을 브라우저로 열면 그대로 동작합니다.

## 세 벌을 따로 둔 이유

직무마다 다른 주소를 내려고 같은 뼈대를 세 벌 둡니다. 제출할 때 링크만 갈아 끼웁니다.

| 지원 직무 | 주소 | 폴더 |
| --- | --- | --- |
| 영업 · 영업관리 · 영업기획 | https://mingeun-git.github.io/ | 루트 |
| 마케팅 | https://mingeun-git.github.io/marketing/ | `marketing/` |
| 데이터 분석 | https://mingeun-git.github.io/data/ | `data/` |

루트와 `marketing/`은 각 직무의 채용공고를 분석해 홈 문구를 따로 썼습니다.
`data/`는 아직 영업용 뼈대 그대로이고, 맨 위 주석에 고쳐야 할 자리를 번호로 적어 뒀습니다.

세 벌이 갈리는 자리는 홈(`index.html`)의 hero 문구, 「일하는 방식」 원칙 3장,
「핵심 역량」 4장, 「공고 대조」 표, 프로젝트 그룹명과 타일 태그, 「다루는 도구」 순서입니다.
프로젝트 상세 7건은 직무와 무관하게 세 벌이 같은 내용을 씁니다.

세 폴더는 `assets/`와 `projects/`를 각자 복사해 갖고 있습니다. 한 벌을 고쳐도 다른 벌이
따라 바뀌지 않습니다. 직무별로 따로 굴리려고 일부러 이렇게 뒀습니다. 공통 CSS를 고쳤다면
세 곳에 모두 반영해야 합니다.

```
.

├─ marketing/                     마케팅용 사본. 마케팅 공고 기준으로 문구를 다시 씀

├─ projects/

│  ├─ recruit-content.html        학회원 모집 콘텐츠와 예산 운용

│  ├─ css/

│  │  └─ main.css                 컴포넌트 스타일. 모든 페이지가 공유
```

## 디자인 기준

**시스템** IBM Carbon Design System v11을 기반으로 합니다. 색상 팔레트는 `@carbon/colors` 원본 hex 값을, 타입 스케일과 간격은 `@carbon/type`과 Carbon spacing scale을 씁니다. 수치와 표가 많은 화면을 위해 만들어진 시스템이라 위계가 촘촘하고 회색 램프의 대비가 강합니다.

**의도적으로 바꾼 세 가지** `tokens.css` 상단 주석에 이유와 함께 적어 뒀습니다. 강조색을 IBM Blue 대신 Teal 70으로 바꾼 것, 한글 본문 행간을 넓히고 타입 스케일 아래쪽 단을 한 단계씩(12→13, 14→15, 16→17, 18→19) 올린 것, 다크 테마 대신 첫 화면과 마지막 화면만 짙은 청록 면으로 뒤집은 것입니다.

**색을 쓰는 규칙** 흰 바탕 위에서는 청록 하나만 강조색으로 씁니다. 주황은 기준선과 미달을 표시할 때만 씁니다. 서로 다른 갈래를 구분해야 할 때만 Carbon의 데이터 시각화 categorical 팔레트 네 색(`--cat-1`~`--cat-4`)을 꺼내 씁니다. 핵심 역량 카드 네 장과 프로젝트 두 묶음이 그 경우입니다.

**토큰** 원시값(`--c-`) → 의미(`--text-`, `--accent-`, `--field-`) → 컴포넌트(`--card-`, `--table-`)의 3계층입니다. `main.css`에서는 색 코드를 직접 쓰지 않고 항상 토큰을 거칩니다. 색을 바꾸려면 `tokens.css`의 원시 팔레트만 손대면 전체가 따라옵니다.

**그래프** 이미지 파일이나 차트 라이브러리를 쓰지 않습니다. 전부 HTML과 인라인 SVG로 그렸습니다.

**동작** 스크롤에 따라 내용이 한 번씩 드러나고, 프로젝트 타일은 마우스를 올리면 살짝 커집니다. 운영체제에서 동작 줄이기를 켠 사용자에게는 두 효과 모두 꺼집니다. 자바스크립트가 없거나 `main.js`가 로드되지 않아도 3초 뒤 모든 내용이 보이도록 안전장치를 넣었습니다.

## 수정하고 다시 배포하기

파일을 고친 뒤 커밋하고 push하면 1분 안에 같은 주소에 반영됩니다.

```bash
git add .
git commit -m "수정 내용"
git push
```

## 프로젝트를 추가하는 방법

1. `projects/` 안에 새 HTML 파일을 만듭니다. `retention.html`을 복사해 내용만 바꾸는 것이 가장 빠릅니다.
2. `index.html`의 해당 묶음 안에 `a.tile` 블록을 하나 더 넣습니다.
3. 앞뒤 프로젝트의 `pager` 링크와 제목을 새 순서에 맞게 고칩니다.

## 상세 페이지의 구조

모든 프로젝트 상세 페이지가 같은 순서를 따릅니다.

| 블록 | 역할 |
| --- | --- |
| `detail-hero` | 제목, 한 문단 요약, 형태와 데이터 규모 등 사실 |
| `narrative` | 왼쪽에 서술, 오른쪽에 그래프 |
| `vizfull` | 오른쪽 칼럼이 너무 길어질 때 마지막 그래프를 전체 폭으로 내리는 자리 |
| `takeaway` | 마지막 한 문단. 짙은 청록 배경 |
| `pager` | 이전 · 다음 프로젝트 |

두 칼럼의 높이는 비슷하게 맞춥니다. 한쪽이 300px 이상 길어지면 `vizfull`의 블록을 오른쪽 칼럼으로 올리거나 그 반대로 내립니다.

## 그래프 종류

| 클래스 | 쓰임 | 조절하는 값 |
| --- | --- | --- |
| `.bars` | 항목별 크기 비교 | `style="--w:70%"` |
| `.steps` | 단계별 축소. 퍼널 | 없음 |
| `.gauges` | 목표 대비 달성률 | `--w`와 목표선 `--at` |
| `.compare` | 전후 두 값 비교 | 없음 |
| `.stack` | 비중 배분 | 각 조각의 `--w` |
| `.dtable` | 수치 표 | 없음 |
| `.cutplot` | 분포와 커트라인 | SVG 좌표 |
| `.quad` | 산점도, 선 그래프 | SVG 좌표 |
| `.match` | 공고의 요구와 내 경험을 한 줄씩 맞대기 (홈 전용) | 없음 |

## 수치의 출처

마케팅 프로젝트 네 건의 수치는 `BDAI_마케팅_성과정리.md`를 따릅니다. 데이터 분석 프로젝트 세 건의 수치는 `데이터분석 포트폴리오/` 안의 각 마스터 문서에 있는 기준표를 따릅니다. 두 곳과 다른 값이 화면에 있으면 문서 쪽이 맞습니다.
